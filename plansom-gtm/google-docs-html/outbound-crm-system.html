PLANSOM · GTM · OUTBOUND CRM SYSTEM

Outbound CRM System

End to end: list building → sourcing database → outreach → HubSpot → qualified handoff → funnel

This is the complete build for the sales-led engine that answers the core question — who is ready to use Plansom today, and why? — by testing named prospects at scale and converting responses into trials. HubSpot is the system of truth; cold sending runs on dedicated infrastructure; qualified people flow into HubSpot at the moment of engagement.

2 · List building — where it happens

Lists are built in Apollo (records + enrichment) and LinkedIn Sales Navigator (social + InMail), from filters that map 1:1 to the Messaging segments and their triggers.

ListFilter (who)Trigger (why now)
A · Teams-native50–500 staff · uses Microsoft Teams/M365 · Ops, PMO, RevOps, CoSWork already lives in Teams
B · Funded scale-upsRaised < 6 months · 20–200 staff · Founder/COO/CoSScaling; coordination breaking
C · Tool-switchersRuns a competing PM/OKR tool · PMO/Head of OpsTool sprawl; open to simpler

List-building process

  1. Define the filter set per list (ICP + trigger) in Apollo / Sales Nav.
  2. Enrich: email, role, company size, funding, tech-stack, Uses-Teams flag.
  3. QA: valid email (verify), role match, dedupe against HubSpot + suppression.
  4. Tag each record with ICP segment + trigger + source before it leaves Apollo.
  5. Cap volume to channel capacity (5 LinkedIn accounts; 170 inboxes).

Where the database is listed (systems of record)

LayerSystemHolds
Sourcing DBApolloAll sourced + enriched prospects; the raw pool
Campaign audienceSending tool (Smartlead/Instantly) + Sales NavContacts actively in a cadence
System of truthHubSpotCanonical record; engagement, deals, lifecycle, attribution

Recommended model: mirror every sourced contact into HubSpot as a non-marketing contact (free) so suppression, dedupe and attribution are centralised — but a contact only becomes a marketing contact / enters the deal pipeline once engaged (see §5).

 

3 · How the database is used for outreach

Finished lists flow from Apollo into the sending tools; each contact runs a two-channel cadence tied to its segment.

ChannelInfraMonthly capacity → output
Email170 inboxes on dedicated domains · warmed · 30 sends/day × 20 days · 3 follow-ups~34k sends → ~102 meetings
LinkedIn5 accounts · Sales Nav + agency tool · 750 connects + 150 InMails / account~125 meetings

Cold sending stays off the primary domain to protect deliverability. Replies sync to HubSpot in real time; a positive reply or booked meeting triggers the handoff in §5.

6 · When qualified people go to HubSpot

Event (in sending tool / LinkedIn)What happens in HubSpot
Positive replyContact promoted to marketing contact · Deal created at ‘Engaged’ · task to owner
Meeting bookedLifecycle = SQL · Deal → ‘Meeting booked’ · meeting source set · Slack alert
Meeting held + qualifiedDeal → ‘Discovery held (SQL)’ · qualification fields required
Trial started (product event)Deal → ‘Trial started’ · handoff to Customer Journey pillar

SQL definition: a booked meeting with an ICP-fit contact whose trigger is confirmed. Everything before that stays in the sourcing/sending layer to keep HubSpot clean and costs down.

10 · End-to-end setup checklist

  1. Stand up sending infra (domains, 170 inboxes, warmup) + 5 LinkedIn accounts.
  2. Build ICP lists A/B/C in Apollo/Sales Nav; enrich + QA + tag.
  3. Connect Apollo → sending tool; Apollo → HubSpot (non-marketing mirror).
  4. Build HubSpot: properties, pipeline + gates, lifecycle, scoring, lists.
  5. Build the 10 workflows; connect Slack + product webhook + sending-tool sync.
  6. Load sequences (email + LinkedIn) with the §4 copy; set enrol/unenrol rules.
  7. Build dashboards; set task queues + SLAs.
  8. QA 10 test contacts end-to-end (source → cadence → reply → SQL → deal → trial).
  9. Go live; review weekly against the §9 funnel.
